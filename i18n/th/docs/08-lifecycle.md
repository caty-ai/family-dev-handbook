# วงจรชีวิตพื้นที่ทำงาน LC — ชั้นที่กำหนดสัญญาการ "นำออก" ของสิ่งที่วางไว้

ในขณะที่ชั้น L (L2 / L1 / L0) เป็นสัญญาว่า "จะดำเนินงานอย่างไร" ชั้น LC จะกำหนดสัญญาว่า **จากสถานที่ที่สิ่งของสะสมอย่างต่อเนื่อง (แหล่งเก็บข้อมูลที่ใช้ร่วมกัน・ไดเรกทอรีทำงาน・จุดส่งมอบ) สิ่งที่วางไว้จะออกไปเมื่อไหร่・อย่างไร** แต่ละกฎมี rule ID ที่เสถียร (`LC-1`〜`LC-5`) กำกับ และระบุขอบเขตการบังคับใช้ของแต่ละข้อไว้ใน〔 〕 ฝั่งสรุป ([docs/04](04-adoption.md)) จะอ้างอิง ID เหล่านี้ ท่าทีเมื่อไม่สามารถตรวจสอบได้ดูที่ [docs/05](05-fail-posture.md)

ที่มา: ต่อให้กำหนดเฉพาะระเบียบฝั่งการเขียน (Issue-first・จะเขียนที่ไหน) **สิ่งที่ไม่มีทริกเกอร์การนำออกจะค้างอยู่เสมออย่างแน่นอน** ชั้น LC คือชั้นที่กำหนด "วิธีออกไป" ให้เป็นคู่กับกฎ "วิธีวาง" ไว้เป็นหนึ่งเดียว ชื่อของแต่ละขั้นตอนใช้คำบทบาทเป็นหลัก ส่วนป้ายภาษาอังกฤษเป็นสัญกรณ์เสริมในวงเล็บ

## LC-1 หลักการทริกเกอร์กำหนดเวลา 〔ทุกที่ที่นำไปใช้〕

**เมื่อวางสิ่งของ ต้องกำหนดทริกเกอร์การนำออก (กำหนดเวลา หรือเงื่อนไขความสมบูรณ์) ไปพร้อมกันเสมอ**

ให้ถือหลักที่ว่า "สิ่งที่ไม่มีทริกเกอร์จะกลายเป็นการเก็บไว้ถาวร" รูปแบบของทริกเกอร์จะเป็นกำหนดเวลา (วันที่・จำนวนวัน) หรือเงื่อนไขความสมบูรณ์ (เมื่อ merge แล้ว・เมื่อจัดสรรแล้ว・เมื่อรวบรวมแล้ว) ก็ได้ หากไม่สามารถแสดงด้วยข้อกำหนดของสถานที่วาง (การตั้งชื่อ・เมตาดาต้ากำหนดเวลา) ได้ ให้เหลือไว้ 1 บรรทัดใน Issue หรือคำประกาศ ณ เวลาที่วาง

## LC-2 วงจรชีวิตทางเดียว 〔บ้านที่มีพื้นที่ต่อเนื่อง〕

**git branch / worktree ไม่อยู่ในขอบเขตของบทนี้ — ต้นฉบับของการทำความสะอาดคือ [L0-4 / L0-8](03-git-protocol.md) (ลบหลัง merge)**

สิ่งที่วางไว้ในพื้นที่ต่อเนื่องจะไหลไปทางเดียวตามลำดับ **รับเข้า (intake) → ใช้งานอยู่ (active) → เสร็จสมบูรณ์ (complete) → จัดเก็บถาวร (archive)** ห้ามไหลย้อนกลับ

- การจัดเก็บถาวร (archive) **ไม่เปลี่ยนแปลง** — สิ่งที่เข้ามาแล้วจะไม่แก้ไข・ไม่ลบ
- เมื่อต้องการกู้คืน จะไม่ลบออกจาก archive แต่ **นำกลับไปยังฝั่งที่ใช้งานอยู่ในรูปแบบสำเนาใหม่**
- แนบบันทึก (manifest) ที่ระบุว่า "ย้ายอะไร・เมื่อไหร่・เพราะเหตุใด และจะนำกลับมาอย่างไร" ไว้ที่ปลายทางจัดเก็บถาวร

## LC-3 การระบุเงื่อนไขการนำออกเป็นลายลักษณ์อักษร 〔บ้านที่มีพื้นที่ทำงานต่อเนื่อง / แหล่งเก็บข้อมูลที่ใช้ร่วมกัน〕

สำหรับ **3 ประเภท** ต่อไปนี้ ให้ **ระบุเงื่อนไขการนำออกพร้อมตัวเลขเป็นลายลักษณ์อักษรไว้ในการตั้งค่าท้องถิ่น**:

1. **ไบนารีขนาดใหญ่** — วัตถุที่ไม่ใช่ข้อความซึ่งมีขนาดเกินกำหนด (ตัวอย่าง: เกิน 1MB ให้นำไปจัดเก็บถาวร)
2. **เวอร์ชันเก่าที่ระบุชัดเจน** — สิ่งที่วางไว้ในชื่อ・ตำแหน่งที่รู้ได้ว่าเป็นเวอร์ชันเก่า (ตัวอย่าง: `旧〜/`・`.bak` เมื่อตรวจพบให้นำไปจัดเก็บถาวรทันที)
3. **การรวบรวมสิ่งของตามกำหนดการ** — ต้นฉบับหลังการรวบรวมไฟล์ดิบที่เกิดขึ้นตามรอบเวลา (ตัวอย่าง: หลังสร้างสรุปรายเดือนแล้ว ให้นำไฟล์ดิบไปจัดเก็บถาวร)

**ต้นฉบับของตัวเลขอยู่ที่ฝั่งการตั้งค่าท้องถิ่น ตัวเลข (จำนวนวัน・ขนาด ฯลฯ) ที่ปรากฏในเนื้อหาของบทนี้ทั้งหมดเป็นเพียง "ตัวอย่าง" และไม่นับเป็นส่วนหนึ่งของสัญญา** (MUST) สัญญาของบทนี้คือ "กรอบ" (การมีเงื่อนไขการนำออกสำหรับทั้ง 3 ประเภท) ส่วนตัวเลขจริงอยู่ที่ฝั่งท้องถิ่น — เป็นวิธีการเดียวกับ [L1-10](02-issue-loop.md) ที่วางรายชื่อโมเดลที่มีคุณสมบัติไว้ในการตั้งค่าท้องถิ่น

## LC-4 ชุด 3 ขั้นตอนการนำออกสำหรับแหล่งเก็บข้อมูลแบบเพิ่มต่อท้าย 〔MUST เฉพาะแหล่งเก็บข้อมูลที่ประกาศเป็นแบบเพิ่มต่อท้ายเท่านั้น〕

**แหล่งเก็บข้อมูลแบบเพิ่มต่อท้าย** = สถานที่จัดเก็บที่ประกาศการดำเนินงานว่าจะไม่แก้ไข・ไม่ลบเนื้อหาที่มีอยู่เดิม **ข้อนี้จะบังคับใช้เป็น MUST เฉพาะกับบ้านที่ประกาศแหล่งเก็บข้อมูลว่าเป็นแบบเพิ่มต่อท้ายเท่านั้น บ้านที่ไม่มีแหล่งเก็บข้อมูลดังกล่าวถือเป็น N/A** — จะไม่บังคับใช้เงื่อนไขนี้กับทุกที่ที่นำไปใช้

การนำออกจากแหล่งเก็บข้อมูลแบบเพิ่มต่อท้าย (การย้ายไปจัดเก็บถาวร) เป็นข้อยกเว้นที่ระบุไว้ชัดเจนเพียงหนึ่งเดียวของหลักการแบบเพิ่มต่อท้าย และต้องดำเนินการด้วย **ชุด 3 ขั้นตอน** ต่อไปนี้เสมอ:

1. **สำรองข้อมูล** — ก่อนการย้าย ให้ถ่ายภาพสแนปช็อตของแหล่งเก็บข้อมูล
2. **ย้าย** — ย้ายไปยังปลายทางจัดเก็บถาวร (เป็นการย้าย ไม่ใช่การคัดลอกที่เหลือต้นฉบับไว้)
3. **ทิ้งตัวชี้ไว้** — เหลือตัวชี้ที่ระบุ "ย้ายไปที่ไหน・เมื่อไหร่・เพราะเหตุใด" ไว้ที่ตำแหน่งเดิม

**การดำเนินการจริงของการนำออกจะทำโดยการปฏิบัติงานด้วยมือของคน / เอเจนต์เสมอ** จะไม่วางการย้าย・การลบแบบอัตโนมัติไว้ในเส้นทางนี้ (→ LC-5)

## LC-5 การตรวจสอบทำได้แค่แจ้งเตือนเท่านั้น 〔ทุกที่ที่นำไปใช้〕

**การตรวจสอบ・lint จะไม่เคลื่อนย้ายไฟล์** สิ่งที่ทำได้มีเพียง ตรวจพบ → รายงานตามรอบเวลา → คน (หรือเจ้าของ) เป็นผู้ตัดสินใจ เท่านั้น จะไม่มีการนำออกอัตโนมัติ

ท่อข้อมูลของ lint เป็นแบบ fail-open ([FP-4](05-fail-posture.md)) — "ความล้มเหลวของการตรวจสอบจะไม่หยุดงาน" (FP-4) กับ "การตรวจสอบจะไม่เคลื่อนย้ายไฟล์" (ข้อนี้) เป็นคู่กัน และการตรวจสอบจะโอนเอียงไปทางอ่านอย่างเดียวเสมอ
