# LC วงจรชีวิตของพื้นที่ทำงาน — ชั้นที่ทำให้การออกจากพื้นที่ของสิ่งที่วางไว้กลายเป็นสัญญา

ในขณะที่ชั้น L (L2 / L1 / L0) เป็นสัญญาว่า "จะดำเนินงานอย่างไร" ชั้น LC จะกำหนดสัญญาว่า **สิ่งที่วางไว้จะออกจากสถานที่ที่สิ่งของสะสมอยู่อย่างต่อเนื่อง (ที่เก็บข้อมูลที่ใช้ร่วมกัน・ไดเรกทอรีทำงาน・จุดส่งต่อ) เมื่อไหร่และอย่างไร** แต่ละกฎกำกับด้วย rule ID ที่คงที่ (`LC-1`〜`LC-5`) และระบุขอบเขตการบังคับใช้ของแต่ละข้อด้วย 〔 〕 ฝั่งสรุป ([docs/04](04-adoption.md)) จะอ้างอิง ID เหล่านี้ ท่าทีเมื่อไม่สามารถตรวจสอบได้ ดูที่ [docs/05](05-fail-posture.md)

ที่มา: แม้จะกำหนดเพียงระเบียบฝั่งการเขียน (Issue-first・จะเขียนที่ไหน) เท่านั้น **สิ่งที่ไม่มีตัวกระตุ้นการออกจะค้างอยู่เสมออย่างแน่นอน** ชั้น LC คือชั้นที่กำหนด "วิธีออก" หนึ่งเดียวที่จับคู่กับกฎการวาง ชื่อของแต่ละขั้นตอนใช้คำภาษาที่บ่งบอกบทบาทเป็นหลัก ส่วนป้ายกำกับภาษาอังกฤษเป็นสัญกรณ์เสริมในวงเล็บ

## LC-1 หลักการตัวกระตุ้นกำหนดเวลา 〔ทุกที่ที่นำไปใช้〕

**เมื่อวางสิ่งของ ต้องกำหนดตัวกระตุ้นการออก (กำหนดเวลา หรือเงื่อนไขความสำเร็จ) ไปพร้อมกันเสมอ**

ให้ถือเป็นข้อสมมติฐานว่า "สิ่งที่ไม่มีตัวกระตุ้นจะถูกเก็บไว้ถาวร" รูปแบบของตัวกระตุ้นจะเป็นกำหนดเวลา (วันที่・จำนวนวัน) หรือเงื่อนไขความสำเร็จ (เมื่อ merge แล้ว・เมื่อจัดสรรแล้ว・เมื่อรวบรวมแล้ว) ก็ได้ หากไม่สามารถแสดงด้วยกฎของสถานที่วาง (การตั้งชื่อ・metadata กำหนดเวลา) ได้ ให้เหลือไว้ 1 บรรทัดใน Issue หรือคำประกาศ ณ เวลาที่วาง

## LC-2 วงจรชีวิตทางเดียว 〔บ้านที่มีพื้นที่ต่อเนื่อง〕

**git branch / worktree ไม่อยู่ในขอบเขตของบทนี้ — ต้นฉบับเรื่องการทำความสะอาดคือ [L0-4 / L0-8](03-git-protocol.md)**

สิ่งที่ถูกวางในพื้นที่ต่อเนื่อง จะไหลไปในทิศทางเดียวคือ **การรับเข้า (intake) → ใช้งานอยู่ (active) → เสร็จสมบูรณ์ (complete) → จัดเก็บถาวร (archive)** ห้ามไหลย้อนกลับ

- การจัดเก็บถาวร (archive) **ไม่เปลี่ยนแปลง** — สิ่งที่เข้ามาแล้วจะไม่เขียนทับ・ไม่ลบ
- เมื่อจำเป็นต้องกู้คืน ไม่ลบออกจาก archive แต่ให้**คัดลอกใหม่แล้วนำกลับไปยังฝั่งที่ใช้งานอยู่**
- แนบบันทึก (manifest) ที่ระบุว่า "ย้ายอะไร・เมื่อไหร่・ทำไม และจะนำกลับมาอย่างไร" ไว้ที่ปลายทางการจัดเก็บถาวร

## LC-3 การเขียนเงื่อนไขการออกให้ชัดเจน 〔บ้านที่มีพื้นที่ทำงานต่อเนื่อง / ที่เก็บข้อมูลที่ใช้ร่วมกัน〕

สำหรับ**3 ประเภท**ต่อไปนี้ ให้**เขียนเงื่อนไขการออกพร้อมตัวเลขไว้ในการตั้งค่าท้องถิ่นอย่างชัดเจน**:

1. **ไฟล์ไบนารีขนาดใหญ่** — ของที่ไม่ใช่ข้อความซึ่งมีขนาดเกินกำหนด (ตัวอย่าง: เกิน 1MB ให้ย้ายไปจัดเก็บถาวร)
2. **เวอร์ชันเก่าที่ระบุชัดเจน** — สิ่งที่วางอยู่ในชื่อ・ตำแหน่งที่รู้ได้ว่าเป็นเวอร์ชันเก่า (ตัวอย่าง: `旧〜/`・`.bak` เมื่อตรวจพบให้ย้ายไปจัดเก็บถาวรทันที)
3. **การรวบรวมของที่เกิดขึ้นเป็นประจำ** — ต้นฉบับหลังจากรวบรวมไฟล์ดิบที่เกิดขึ้นเป็นระยะ (ตัวอย่าง: หลังจากสร้างสรุปรายเดือนแล้ว ให้ย้ายไฟล์ดิบไปจัดเก็บถาวร)

**ต้นฉบับของตัวเลขอยู่ที่ฝั่งการตั้งค่าท้องถิ่น ตัวเลข (จำนวนวัน・ขนาด ฯลฯ) ที่ปรากฏในเนื้อหาของบทนี้ล้วนเป็น "ตัวอย่าง" และไม่นับเป็นสัญญา** (MUST) กรอบ (การมีเงื่อนไขการออกสำหรับ 3 ประเภท) คือสัญญาของบทนี้ ส่วนตัวเลขจริงเป็นของท้องถิ่น — เป็นวิธีการเดียวกับการวางรายชื่อโมเดลที่มีคุณสมบัติไว้ในการตั้งค่าท้องถิ่นตาม [L1-10](02-issue-loop.md)

## LC-4 ชุด 3 ขั้นตอนการออกของที่เก็บข้อมูลแบบ append-only 〔MUST เฉพาะที่เก็บข้อมูลที่ประกาศว่าเป็น append-only เท่านั้น〕

**ที่เก็บข้อมูลแบบ append-only** = สถานที่จัดเก็บที่ประกาศการดำเนินงานว่าจะไม่เขียนทับ・ไม่ลบเนื้อหาที่มีอยู่เดิม **ข้อนี้ใช้บังคับเป็น MUST เฉพาะกับบ้านที่ประกาศว่าที่เก็บข้อมูลของตนเป็นแบบ append-only เท่านั้น บ้านที่ไม่มีที่เก็บข้อมูลดังกล่าวถือเป็น N/A** — ไม่บังคับข้อสมมติฐานนี้กับทุกที่ที่นำไปใช้

การออกจากที่เก็บข้อมูลแบบ append-only (การย้ายไปจัดเก็บถาวร) เป็นข้อยกเว้นที่เขียนไว้ชัดเจนเพียงข้อเดียวของหลักการ append-only และต้องดำเนินการด้วย**ชุด 3 ขั้นตอน**ต่อไปนี้เสมอ:

1. **สำรองข้อมูล** — ก่อนการย้าย ให้ถ่ายภาพสแนปช็อตของที่เก็บข้อมูล
2. **ย้าย** — ย้ายไปยังปลายทางจัดเก็บถาวร (เป็นการย้าย ไม่ใช่การคัดลอกที่เหลือต้นฉบับไว้)
3. **เหลือตัวชี้ไว้** — เหลือตัวชี้ที่ระบุว่า "ย้ายไปที่ไหน・เมื่อไหร่・ทำไม" ไว้ที่ตำแหน่งเดิม

**งานจริงของการออกจะดำเนินการด้วยการทำงานด้วยมือของคน / เอเจนต์เสมอ** อย่าวางการย้าย・การลบแบบอัตโนมัติไว้ในเส้นทางนี้ (→ LC-5)

## LC-5 การตรวจสอบมีไว้เพื่อแจ้งเตือนเท่านั้น 〔ทุกที่ที่นำไปใช้〕

**การตรวจสอบ・lint จะไม่ขยับไฟล์** สิ่งที่ทำได้คือ ตรวจจับ → รายงานตามระยะ → ให้คน (หรือเจ้าของ) เป็นผู้ตัดสินใจ เท่านั้น จะไม่ทำการออกอัตโนมัติ

ท่อข้อมูลของ lint เป็น fail-open ([FP-4](05-fail-posture.md)) — "ความล้มเหลวของการตรวจสอบจะไม่หยุดงาน" (FP-4) กับ "การตรวจสอบจะไม่ขยับไฟล์" (ข้อนี้) เป็นคู่กัน และการตรวจสอบจะเอนไปทางอ่านอย่างเดียวเสมอ
