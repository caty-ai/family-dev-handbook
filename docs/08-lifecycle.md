# LC ワークスペース・ライフサイクル — 置いた物の退場を契約にする層

L 層（L2 / L1 / L0）が「作業をどう進めるか」の契約であるのに対し、LC 層は**物が持続的に溜まる場所（共有ストア・作業ディレクトリ・受け渡し場所）から、置いた物がいつ・どうやって出て行くか**の契約を定める。各ルールに安定 rule ID（`LC-1`〜`LC-5`）を付し、条ごとに適用対象を〔 〕で明記する。要約側（[docs/04](04-adoption.md)）はこの ID を参照する。検証できない時の姿勢は [docs/05](05-fail-posture.md)。

背景: 書き込み側の規律（Issue-first・どこに書くか）だけを定めても、**退場トリガーの無いものは必ず滞留する**。置き方のルールと対になる「出て行き方」を1つに定めるのが LC 層である。段階の名前は役割語を正とし、英語ラベルは括弧の補助表記とする。

## LC-1 期限トリガー原則〔全導入先〕

**物を置く時に、退場トリガー（期限 or 完了条件）を必ず一緒に決める。**

「トリガーの無いものは永久保持になる」前提で扱う。トリガーの形は期限（日付・日数）でも完了条件（マージされたら・振り分けたら・集約したら）でもよい。置き場所の規約（命名・期限メタデータ）で表せない時は、置く時点の Issue または宣言に1行残す。

## LC-2 一方通行ライフサイクル〔持続領域を持つ家〕

**git branch / worktree は本章の対象外 — 掃除の正本は [L0-4 / L0-8](03-git-protocol.md)。**

持続領域に置かれた物は、**受け取り（intake）→ 現役（active）→ 完成（complete）→ 退蔵（archive）**の一方通行で流れる。逆流させない。

- 退蔵（archive）は**不変** — 入った物は書き換えない・消さない
- 復元が必要な時は archive から消さず、**新規コピーとして現役側へ戻す**
- 退蔵先には「何を・いつ・なぜ移したか、どう戻すか」の記録（manifest）を添える

## LC-3 退場条件の明文化〔持続ワークスペース / 共有ストアを持つ家〕

次の**3類型**について、**数値つきの退場条件をローカル設定に明文化**する:

1. **重量バイナリ** — 一定サイズを超える非テキストの置き物（例: 1MB 超は退蔵へ）
2. **明示的な旧版** — 旧版と分かる名前・場所に置かれた物（例: `旧〜/`・`.bak` は検知され次第退蔵へ）
3. **定期物の集約** — 定期的に発生する生ファイルの集約後の原本（例: 月次ダイジェスト生成後、生ファイルは退蔵へ）

**数値の正本はローカル設定側にあり、本章の本文に現れる数字（日数・サイズ等）はすべて「例」であって契約に数えない**（MUST）。枠（3類型に退場条件を持つこと）が本章の契約で、実数はローカルが持つ — 適格モデル名簿をローカル設定に置く [L1-10](02-issue-loop.md) と同じ方式である。

## LC-4 追記型ストアの退場3点セット〔追記型と宣言したストアに限り MUST〕

**追記型ストア**＝既存内容の書き換え・削除をしない運用を宣言した保存場所。**本条は、ストアを追記型と宣言した家にだけ MUST として適用される。該当するストアを持たない家は N/A** — この前提を全導入先に課さない。

追記型ストアからの退場（退蔵への移動）は追記型原則の唯一の明文例外であり、必ず次の**3点セット**で行う:

1. **バックアップ** — 移動の前に、ストアのスナップショットを取る
2. **移動** — 退蔵先へ移す（元を残すコピーではなく移動）
3. **ポインタ残置** — 元の位置に「どこへ・いつ・なぜ移したか」を指すポインタを残す

**退場の実作業は常に人 / エージェントの手動操作**で行う。この経路に自動化された移動・削除を置かない（→ LC-5）。

## LC-5 検査は警告のみ〔全導入先〕

**検査・lint はファイルを動かさない。** やってよいのは、検知 → 定期レポート → 人（またはオーナー）が判断、まで。自動退場はしない。

lint の情報配管は fail-open（[FP-4](05-fail-posture.md)）—「検査の故障が作業を止めない」（FP-4）と「検査がファイルを動かさない」（本条）は対であり、検査は常に読み取り専用に倒す。
