# B 委譲ブリーフ — 1回の委譲を契約にする層

L 層（L2 / L1 / L0）がレーンと人の間の契約であるのに対し、B 層は**エージェントがサブエージェント（実装 worker・レビュー席・別の CLI エージェント）へ仕事を1回渡すときの依頼文の契約**を定める。各ルールに安定 rule ID（`B-1`〜`B-5`）を付す。要約側（[docs/04](04-adoption.md)）はこの ID を参照する。様式の正本は [templates/brief-template.md](../templates/brief-template.md)。検証できない時の姿勢は [docs/05](05-fail-posture.md)。

背景: レーンの引き継ぎは Issue が SoT（[L1-1](02-issue-loop.md)）で守られるが、**委譲1回ごとの品質はレーン規律だけでは守れない**。委譲先はこちらの会話履歴を持たず（fresh context）、依頼文に書かれなかったことは存在しないのと同じになる。依頼文そのものを小さな契約にするのが B 層である。

## B-1 3層ブリーフの必須構造

実質的な委譲（コード・文書の実装 / 修正 / 生成を伴うもの）の依頼文には、次の3セクションを必ず含める:

1. **実装仕様（Goal）** — ゴール・制約・前積みの文脈・触ってよい範囲
2. **実装チェック（Self-verification）** — 納品前に作業者自身が回す検証リスト
3. **レビュー基準（Reviewer criteria）** — 後段のレビューが見る観点

実装を伴うブリーフの「実装チェック」には**「追加・変更したテストと、その実行結果」を標準項目として含める**（[T-3](10-test-ci-baseline.md)。テストを追加しなかった場合は理由つきで報告する）。

理由: 仕様だけ渡すと「できました」が検証不能になる。何をもって完成とするか（自己検証）と、何を疑って見るか（レビュー観点）を**委譲の時点で**渡すことで、納品物を主張ではなく証拠で判定できる（[L1-7](02-issue-loop.md) と同じ向き）。

## B-2 適用条件 — 迷ったら付ける

- **必須**: 実装・修正・生成を伴う委譲。サイズ S でも、成果物がリポジトリに残るなら付ける
- **免除**: 読み取り専用の検索・調べ物・短い質問（成果物がその場で読み捨てられるもの）
- 迷ったら付ける（重い側 — [L2-1](01-milestone-loop.md) の重さ判定と同じ姿勢）

## B-3 Issue が正本 — ブリーフは導出物

- ブリーフの Goal / 完了条件 / 触ってよい範囲は、担当 Issue の **Why / Done when / 触るファイル予測**（[L1-2](02-issue-loop.md)）から導出する
- ブリーフと Issue が食い違ったら **Issue が正**。食い違いに気づいた者は先に Issue を直してから委譲する — 黙って乖離させない（[L1-8](02-issue-loop.md) と同じ向き）
- 1つの Issue から複数のブリーフが出るのは正常（実装・修正ラウンド・レビュー席でそれぞれ別のブリーフ）

## B-4 文脈は前積み — 探索させない

- 委譲先が必要とする事実（パス・仕様・制約・禁止事項・環境の癖）はブリーフに**前積み**する。委譲先の探索頼みにしない
- 理由: 探索は委譲先ごとに結果が揺れる。read-only の席や sandbox 環境では探索自体ができないことがある。前積みは、fresh context でも read-only でも同じ品質を成立させる唯一の方法
- レビューを委譲するときは**最悪の失敗形を名指しする**（「この変更で一番まずいのは◯◯が起きること」）。「バグを探せ」より検出の的が揃う
- ブラインドが必要な委譲（独立レビュー席）では、他席の指摘・自分の事前分析を**混ぜない**。前積みするのは事実であって、結論ではない

## B-5 様式は機械検査できる形に保つ

- 3セクションは**固定の見出し文字列で機械判定できる**形を保つ（自由記述に溶かさない）。見出し文字列は各家でローカライズしてよいが、決めたら固定する
- 委譲ツール側で欠落を着手前にブロックする検査（フック等）を置くことを推奨する。検査の実装はこのハンドブックのスコープ外（各家のツール層に属する）
- **検査が無い環境でも B-1〜B-4 は契約として有効** — fail-open は「様式不要」を意味しない（[docs/05](05-fail-posture.md) の向き）
