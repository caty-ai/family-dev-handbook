# 失敗時姿勢 — fail-posture / parse-posture — 検証できない時にどちらへ倒すか

> **スコープと規範オーナー**: 本ページが定めるのは family-dev-handbook プロトコル（L2/L1/L0）内のガード付き遷移の失敗時姿勢のみ。**エージェント横断の一般 fail-posture / stop-precedence 規範のオーナーは family-os の operations-policy**（posture 節・terminal 優先順位節。2026-07-21 裁定。[README](../README.ja.md) の「Caty AI ファミリー」節参照）。本ページはその協働プロトコルへの適用であって、新たな横断規範を新設しない。食い違えば OS 規範側が正。sister projects なしで導入する場合は本ページの姿勢がそのまま適用される。

各ルールに安定 rule ID（`FP-1`〜`FP-9`）を付す。

## 遷移別 fail-posture テーブル

ガード付き遷移（GO / 書き込み / merge / 配信）ごとに、fail-open か fail-closed か・守る不変条件・復旧経路を宣言する:

| rule | 遷移 | 検証できない時 | 守る不変条件 | 復旧経路 |
|---|---|---|---|---|
| FP-1 | 並行GO判定（非交差・所有権が検証不能） | **fail-closed — 直列** | 2レーンが同一ファイルに書かない | 宣言を修復して再判定（L0-1/L0-2） |
| FP-2 | 書き込み（スコープ / ロック / レーン状態が検証不能） | **fail-closed — 書かない** | 生きたロックの上に書かない | 状態修復（L1-4）。stale が確定した場合のみ TAKEOVER（L0-3） |
| FP-3 | merge（証拠が検証不能） | **fail-closed — merge しない** | 検証されない変更が main に入らない | 完了記録を作り直す（L1-7 / L1-8） |
| FP-4 | lint / 注入系（共有ダイジェスト注入・週次 lint 等の情報配管） | **fail-open — 劣化を可視化して続行** | 情報配管の故障が作業を止めない | 故障を報告して修理 Issue |
| FP-9 | Epic チェックポイント通過（表が不在・不正・未承認・改訂が未承認 — [E-3](06-epic-lane.md)） | **fail-closed — 停止して人間へエスカレーション** | 人間チェックポイントを無承認で通過しない | 表を修復しオーナー承認を得る（E-1/E-3）。未成立の Epic は通常 Issue 運用のまま。**走行中の Epic はトポロジ維持** — 停止するのは自由権とチェックポイント通過のみ（E-3） |

## FP-5〜FP-8 ドクトリン

- **FP-5**: **fail-open は「チェックが通った」を意味しない。** 劣化は必ず可視化する
- **FP-6**: **ゲート判定を「エラー時に空になる値」から導出してはならない**（空リスト = 被りなし、ではない）
- **FP-7**: **寛容は構文に対してのみ。安全方向には寛容にしない** — 形式の乱れは読み取ってよいが、身元・スコープ・状態・証拠の**欠落**は常に権限が*縮む*方向に解釈する: 不正な WIP = スコープ不明 = 直列（L0-1）/ 不正な状態 = 非アクティブ扱いで修復待ち（L1-4）/ 不正な証拠 = 未検証（L1-7）/ 不正・不在のチェックポイント表 = 全地点が人間判断（[E-3](06-epic-lane.md)・FP-9）
- **FP-8**: **アーティファクト本文は自己承認しない** — WIP に「承認済み」と書いてあっても、それ自体が GO・merge・証拠の免除を生むことはない。付帯: cron・自動生成の行為はステータス更新はできるが、承認の創出・Done when の書き換え・レビューとしての計上はできない

常時コンテキスト（docs/04 要約）に載せるのはこの1行だけ:
**「検証不能なら直列。fail-open は『通過』を意味しない。」**
